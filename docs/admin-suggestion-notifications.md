# 관리자 건의함 알림

학생의 새 건의가 저장된 후, 알림을 켠 관리자 기기로 웹 푸시를 보낸다. 수정·답변·삭제에는 발송하지 않는다. 모든 지점의 새 글을 받으며 알림을 누르면 해당 지점을 선택하고 글을 강조한다. 학생 이름과 글 내용은 잠금화면에 표시하지 않는다.

## 최초 설정

1. 실제 TREE Supabase 프로젝트 `tjonmlclhhinjwgllthx`의 SQL Editor에서 `supabase/admin_suggestion_notifications.sql` 전체를 실행한다. 마지막 조회의 두 행이 `row_security=true`, `anon_can_read=false`, `authenticated_can_read=false`인지 확인한다.
2. 기존 서버 환경변수 `NEXT_PUBLIC_SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `ADMIN_KEY`가 있어야 한다. 관리자 로그인 후 알림 화면이 서명 키를 한 번 생성해 서비스 전용 테이블에 보관한다. 별도의 새 환경변수는 필요 없다.
3. 알림 받을 휴대폰에서 `https://www.themonster.kr/tree/admin/suggest`에 관리자 로그인한다. 안드로이드는 Chrome에서 ‘이 기기 알림 켜기’를 누른다. 아이폰·아이패드는 Safari에서 ‘공유 → 홈 화면에 추가’ 후 추가된 아이콘으로 열어 같은 버튼을 누른다. 기기의 알림 허용을 선택한다.
4. ‘테스트 알림 받기’를 눌러 해당 기기에서 수신 및 탭 이동을 확인한다. 실제 학생의 새 건의가 올라오면 잠금화면 수신과 해당 지점·글 이동을 확인한다.

DB 설정 전에는 ‘연결 준비 중’ 안내가 표시되며 알림을 켤 수 없다. 건의 저장은 계속 동작한다. 2026-09-09 작업 시 연결된 Supabase 도구는 TREE 프로젝트 접근 권한이 없어 SQL을 적용하지 못했다. 따라서 코드 검증은 실제 휴대폰 수신 완료를 의미하지 않는다.

## 운영 동작

- `/tree/admin/sw.js`는 관리자 전용 서비스 워커다. 학생 워커 및 포인트 알림 구독은 변경하지 않는다.
- 관리자 비밀번호를 바꾸면 이전 비밀번호로 등록한 기기는 새 건의 수신 대상에서 제외된다. 받을 기기에서 새 비밀번호로 로그인하고 다시 알림을 켠다.
- ‘알림 끄기’는 해당 기기의 서버 등록을 제거한다. 만료 응답(404/410)은 해당 구독만 제거하고, 일시적인 발송 오류에서는 구독을 유지한다.
- 전송은 Next.js `after()`에서 수행하며 시간 제한이 있다. 영속 재시도 큐는 없으므로 일시적인 푸시 공급자 장애 시 해당 알림이 누락될 수 있다. 건의 원문은 건의함에서 확인할 수 있다.
- 등록 및 발송은 관리자 쿠키 인증과 서비스 전용 DB 권한을 사용한다. 웹 푸시 주소와 암호화 키를 검증하고, 알림 링크는 같은 사이트의 관리자 건의함으로 제한한다.

## 검증

`node scripts/test-admin-suggestion-notifications.mjs`, `npm run typecheck`, 변경 파일 ESLint로 확인한다. 테스트는 가짜 DB와 전송기를 사용하고 실제 학생 데이터나 기기로 알림을 보내지 않는다. `/tree/suggestion-notification-preview`는 Vercel preview에서만 열리며 버튼은 미리보기 상태만 변경한다.
